## 02 — build / break / understand

The way I usually learn:

**read → build → break → stare at logs → trace the problem → fix it → document it**

Reading tells me how something is supposed to work.

Breaking it usually tells me **why**.

So this GitHub isn't really a museum of finished projects.
It's closer to a working archive of systems I've built, misconfigured, attacked, debugged and tried to understand a little better.
